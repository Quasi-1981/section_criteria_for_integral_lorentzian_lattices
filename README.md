## Reproducing

```
cd src
python S1764_genus_enum_agm.py --outdir .
python S1756_genus_pinning.py --outdir . -B 2
python S1678_cost_formula.py --outdir .
python S1758_supplementary_build.py --outdir ../supplementary
```

The typeset artefacts are rebuilt from the Markdown with

```
python src/S1765_build_tex.py --md section_criteria_en.md --out section_criteria_en.tex \
       --title "..." --author "..." --date "..."
pdflatex section_criteria_en.tex   # twice
```

That builder ends with a **glyph gate**: any character its map does not know is reported by
name, because an unmapped character does not raise an error — it disappears silently from
the PDF. The shipped `.tex` was produced by it and passes that gate.

Python 3 with `sympy` and `numpy`. Each probe prints the output recorded beside it in `*_run.log`.
Every log in this package was **regenerated by execution**, not edited.

All Markdown files are UTF-8 **without BOM**; on Windows PowerShell 5.1, read them with
`Get-Content -Encoding UTF8` (the default rendering otherwise shows mojibake).

## Two notes, so that nothing looks like an oversight

**On the negative controls.** Several probes end with a block of controls, each of which was required
to be able to **fail** before its result was allowed to count. One of them is worth naming: an earlier
run of `S1756_genus_pinning.py` returned "no counterexamples found" over 65 667 lattices — and that
number was **void**, because every genus invariant available to that probe turned out to be a function
of the very triple being tested. The probe now carries a control (`K-POWER`) that detects exactly this
and reports the run as blind rather than as negative evidence. The verdict of §3.5 is therefore not
taken from an absence of counterexamples but from a counting argument: the enumeration from above
gives seven genera, the explicit Grams from below give seven realised triples, and the triple is a
genus invariant — so the map genus → triple is injective.

**On the identifiers.** The probes are named by short labels such as `S1764`. These are not references
to a private system: each is a file in this repository, bound in the table above to the statement it
supports. Every log was produced by running the file as it stands here.
